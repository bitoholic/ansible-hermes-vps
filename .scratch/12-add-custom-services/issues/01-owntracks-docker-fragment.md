# Ticket #01: OwnTracks Docker service fragment

**Blocked by:** none
**Blocks:** #02–#05

## Description

Create the OwnTracks recorder Docker service fragment for the consolidated compose stack:

1. **Service fragment** at `roles/docker/templates/services/owntracks.yml.j2`:
   - Image: `owntracks/recorder:latest` (or pinned version tag)
   - Container name: `owntracks`
   - Port: 8080 (container), exposed on `gateway` network only — **no host port binding**
   - Volume: named `owntracks_data` → `/store` (SQLite storage)
   - Environment:
     - `OTR_HOST=[IP_ADDRESS]` (bind all interfaces inside container)
     - `OTR_PORT=8080`
     - `OTR_AUTH_FILE=/store/htpasswd` (basic auth file)
     - `OTR_STORE=/store` (data directory)
   - Networks: `gateway`
   - Restart policy: `unless-stopped`
   - User: `llm_wiki` (UID/GID 10000) — consistent with other services

2. **Volume**: add `owntracks_data` to `docker_volumes` in `roles/docker/defaults/main.yml`

3. **Enable service**: add `owntracks` to `docker_enabled_services` in `roles/docker/defaults/main.yml`

## Acceptance criteria

- `roles/docker/templates/services/owntracks.yml.j2` renders a valid Docker Compose service fragment
- `owntracks` appears in `docker_enabled_services` list
- `owntracks_data` appears in `docker_volumes` list
- `docker compose config` validates successfully
- No host ports published for Owntracks (Caddy proxies on gateway network)

## Notes

- The fragment pattern is established in epic 11. Check `roles/docker/templates/services/caddy.yml.j2` for reference.
- Owntracks runs as `llm_wiki` user, so the `owntracks_data` volume must be accessible by UID 10000.
- Basic auth file (`htpasswd`) will be generated by a separate task before container start (ticket #05).

# 03: Structural guard — a plaintext secrets file can't be committed

**What to build:** A check in the standard lint run that makes committing plaintext secrets structurally impossible to miss: the tracked encrypted store must be genuinely encrypted and satisfy the name-set rule, no other tracked file may look like a plaintext secrets file, and `.env` must stay untracked.

**Blocked by:** #01
**Blocks:** #09

**Status:** done

- [x] The **name-set rule** is defined once and used by this guard: every *required* manifest name is present in the store; every name present is a manifest name or a *declared extra*; **declared extras are listed in exactly one place — the generator's existing operator-extras list** — and this ticket adds the audit extra-terms entry there (its name fixed here and used by epic 24's audit) alongside the target host; optional manifest entries with defaults may be absent
- [x] When the encrypted secrets file is tracked, the guard asserts it carries SOPS metadata, every value is encrypted, and its names satisfy the name-set rule
- [x] No other tracked file matches a plaintext-secrets pattern; `.env` is untracked and ignored
- [x] Negative fixtures demonstrate each failure: a cleartext value, a missing required name, an undeclared extra name, and a tracked plaintext-secrets-looking file; a fixture proves an absent *optional* name and a declared extra both pass
- [x] **The mandatory state is derived, not switched by hand:** when the SOPS recipient configuration is present the store must be present and valid, and a missing store is a failure; when neither is present (before the migration, and in a fresh clone of a public export, which deliberately has neither) the guard applies only its store-independent checks — no plaintext secrets file tracked, `.env` untracked — and the standard lint run passes; the migration ticket (#09) therefore needs no manual flip, and a negative case shows that deleting the store while the recipient configuration remains fails
- [x] The guard runs in the standard lint run and needs no key

## Notes

See epic 22 spec, "Implementation Decisions" (name-set rule; structural guard). Note the generated template already treats the target host as an extra outside the manifest, and 19 of the manifest's entries are optional — a plain "names equal the manifest" check would be wrong.

## Implementation notes

**Deliverables.** `scripts/check_secrets_store.py` (the guard; needs no key, reads only names and SOPS structure), `tests/check-secrets-store.sh` (negative and positive fixtures; wired into `tests/lint.sh`), and the single name-set rule: `name_set_problems` / `apply_name_set` in `scripts/hermes_secrets.py`, which the deploy wrapper's preflight now also uses (so the wrapper, the guard, and — in the next tickets — the helper and epic 24's audit share one definition). The **declared extras** stay in exactly one place, `EXTRA` in `scripts/generate-env.py`, which now carries a *required* flag per entry: `TARGET_HOST` (required) and the new **`AUDIT_EXTRA_TERMS`** (optional; a comma-separated list of extra terms for epic 24's audit — this ticket fixes its name). The generated `.env.template`/`setup-env.sh` were regenerated and their sync check passes.

**What the guard asserts.** *Derived mandatory state:* if `.sops.yaml` is on disk the store must be too (deleting the store while the configuration remains fails); with neither present — before the migration and in a public export — only the store-independent checks run and the standard lint passes; a store without `.sops.yaml`, or a git-ignored store, fails. *A present store is genuinely encrypted:* SOPS metadata (`sops_version`, `sops_mac`, an age recipient entry), every value an `ENC[AES256_GCM,…]` blob (a name ending in `_unencrypted`, which SOPS itself leaves in cleartext, is refused like any other cleartext value; encrypted comments are allowed), no duplicate names, and the name-set rule (missing required names and undeclared names reported **by name only**; an absent optional name and a declared extra pass). *`.sops.yaml`:* each rule needs a `path_regex` (recipients scoped), at least one age recipient in age-public-key form, at least one rule must match the store's path, and none may weaken value encryption (`unencrypted_*`, `encrypted_*`, `mac_only_encrypted`). *Store-independent:* `.env` untracked **and** git-ignored (the tripwire); no other tracked file named `.env`, `*.env` (other than the store), `.envrc` or `.env.<x>` (other than `.template`/`.example`/`.sample`); and no tracked file whose **content** has three or more distinct manifest/extra names assigned real-looking values — inline comments, empty values, placeholders (`%s`, `<…>`, `$…`, `{{`, `example`, `test`, `fake`, …) and all-caps fixture stand-ins (`WIKI_KEY`) are ignored, which is how the names-only template, the resolver test's crafted environment and documentation pass while a pasted `.env` fails.

**Tests.** 40-odd cases in throwaway git repositories with a throwaway age key, run with **no key file and no key environment** (the guard needs none): a clean fixture; optional names absent and a declared extra present; missing required name; undeclared name; cleartext value; `_unencrypted` name; stripped metadata; a non-SOPS file; a duplicated name; store deleted while `.sops.yaml` remains; neither present; store without configuration; five `.sops.yaml` weakenings/scoping failures; `.env` not ignored / tracked; a tracked `*.env`; a tracked file whose content looks like a `.env` (values never printed); the names-only template, fixture-style values and prose passing; two names below the threshold. **Mutation-checked:** 24 mutants of the guard (each check removed or inverted, the derived state, the thresholds, value printing) — all caught. **Honest limits (in the guard's docstring):** it cannot verify that ciphertext decrypts (the wrapper's preflight does), nor history (epic 24); the content heuristic is a tripwire — a plaintext file whose values are all upper-case-and-underscore, or that contains `test`/`example` in each value, would pass it.

## Review round 1 — CHANGES REQUIRED (five blocking; fixed)

Independent review (the guard passed on the real repository and did not break the wrapper; the name-set rule confirmed single-sourced). Blocking, all reproduced: **B1** a plaintext value under a `sops_`-prefixed name passed (every such name was skipped as metadata, and SOPS ignores unknown ones, so it would survive a real deploy and a commit); **B2** a `#ENC[AES256_GCM,` comment line accepted arbitrary text after it; **B3** `ENC[…]` matched plaintext dressed as ciphertext (`ENC[AES256_GCM,data:hunter2secret,iv:AAAA,tag:BBBB,type:str]`); **B4** a false positive on a real SOPS-produced store — SOPS leaves an empty value as an empty string, and an imported `.env` at migration plausibly has an empty optional entry (`AUDIT_EXTRA_TERMS=`); **B5** ten protective checks could be removed without any test failing. **Fixes:** only the exact SOPS metadata names are accepted, each with its shape (`sops_version`, `sops_mac` as an ENC blob, an ISO `sops_lastmodified`, `sops_unencrypted_suffix` only at its default, age recipient as an age public key, age data key as an age-encrypted file; any other `sops_*` name — including `sops_mac_only_encrypted` — is refused); ciphertext must have the real shape (44-character IV, 24-character tag, base64 data, a known `type:`), comments the same with `type:comment`; an empty value is accepted; `sops_version`, `sops_lastmodified`, an age data key **and** a recipient are all required. Also applied from the non-blocking list: names compared case-insensitively (`.ENV`, `prod.ENV`), `.env.j2` accepted as a template, **untracked-but-not-ignored** files scanned as well (a `git add -A` would commit them), YAML `NAME: value`, JSON `"NAME": "value"`, `NAME = value`, `- NAME=value` and BOM-prefixed forms recognised by the content heuristic (the colon form only when followed by whitespace, which keeps `"NAME:key"` lists in tests from matching), the `.env` ignore check no longer honours a user-global ignore, and `key_groups: [null]` no longer crashes. **Tests:** 30 new fixtures — every hiding place above, each metadata removal/alteration, the ciphertext type set, stray and plaintext comment lines, the required extra `TARGET_HOST` at guard level, `.envrc`/`.env.local`/nested `.env`/case variants, an untracked `*.env`, `.env.j2`, YAML/JSON/BOM plaintext files, a git-ignored store, `mac_only_encrypted` and a null key group in `.sops.yaml`, a comma-separated recipient string, an empty optional value — none printing a value. **Mutation-checked:** 27 further mutants of the guard and the name-set code, all caught.

# 01: Deploy wrapper tracer — run a playbook (or a registered script) with decrypted secrets in its environment only

**What to build:** A single command that runs the repository's own playbook — and, in a separate script mode, registered operator scripts — with values from an encrypted secrets file injected into that process's environment and nowhere else, proven end to end against a fixture store and a throwaway age key generated at test time. It checks its prerequisites first, accepts only vetted invocation shapes, streams output live, and returns the child's exit status. It fixes the shape of the SOPS configuration (recipients scoped to the file's path) so later tickets and the migration slot in.

**Blocked by:** None (can start immediately)
**Blocks:** #02, #03, #04, #08, #09

**Status:** done

- [x] A throwaway age key and a fixture encrypted store are generated at test time; no real key or secret is needed to run the test
- [x] The wrapper decrypts into the child process's environment only; no plaintext file is created at any point — including by Ansible itself — asserted by searching the working tree, the temporary directory and every location Ansible could log or cache to for the fixture values after a run
- [x] The `secrets` resolver receives the fixture values, proving the seam's contract works unchanged — the existing resolver test and the single-seam lint check pass untouched
- [x] **Vetted invocation shapes only:** the wrapper runs only the repository's own playbook and passes through a fixed set of flags (check mode, diff, tags, skip-tags, limits, verbosity, start-at-task); it **refuses** extra-variable injection, ad-hoc modules, other playbooks and paths outside the repository, each shown by a negative test
- [x] **Script mode:** the wrapper can run a registered operator script (an allowlist kept in one place) with the same decrypted environment and the same redaction, so scripts get the target host from the store; an unregistered script is refused
- [x] **Ansible's own file writes are pinned off:** the wrapper points Ansible at a pinned configuration, clears inherited `ANSIBLE_*` settings it does not set itself, and refuses to run if the effective configuration would make Ansible write a log file, callback-plugin output or a persistent fact cache to disk; negative tests show each is refused (an inherited environment setting, a setting in the repository's own configuration file, and a callback that logs), because both the configuration file and the environment are editable by an agent and Ansible's own writes bypass the redactor
- [x] The target host is read from the store
- [x] The store is read from a configurable location that defaults to this repository's, so the working repository and the secrets' home can be split later without a rewrite (tested with the store at a non-default path)
- [x] The exit status equals the child's, and output streams live rather than arriving at the end
- [x] Preflight verifies: SOPS and age installed; the operator's key present and not group- or world-readable; the encrypted store valid; required manifest names present — failures name missing secrets by name only and exit non-zero before anything runs
- [x] A committed SOPS configuration scopes recipients to the store's path and is shaped to accept one key per workstation plus a break-glass key; the key source is configurable so a hardware-backed key can be adopted later without a rewrite *(deviation, deliberate: the real `.sops.yaml` is written by the helper (#04) at migration (#09) because it needs real public keys, and the structural guard (#03) derives "store mandatory" from its presence; the shape is proven by the fixture, and the key source is configurable via `HERMES_SECRETS_KEY_FILE` / `SOPS_AGE_KEY_CMD`, tested)*
- [x] The standard lint run fails with a clear message if SOPS or age is missing (it does not skip silently)
- [x] A leftover plaintext `.env` produces a warning

## Notes

See epic 22 spec, "Implementation Decisions" (tool choice; the seam's contract is untouched; recipients; deploy wrapper) and "Testing Decisions" (the one new seam). ## Implementation notes

**Deliverables.** `scripts/deploy` (the wrapper), `scripts/hermes_secrets.py` (store location, name-set inputs, in-memory decrypt, preflight, script registry), `scripts/hermes_redact.py` (the redaction seam — a pass-through until #02), `scripts/registered-scripts.conf` (the one allowlist of script-mode scripts), `tests/check-deploy-wrapper.sh` + `tests/support/deploy-fixture.sh` (the black-box guard and the fixture builder that #02–#04 reuse), and the lint wiring (which now also fails clearly if `sops`/`age` are missing).

**Design decisions**
- **Repository root comes from the wrapper's own location, never the environment.** A copy of `scripts/` in a fixture tree therefore operates on that tree only, which is how the test runs the *real* wrapper against a fixture without any `--root`-style override an agent could abuse.
- **Decrypt via `sops decrypt --output-type json`**, so values round-trip exactly (quotes, newlines, non-ASCII never pass through a dotenv parser) and nothing touches disk.
- **Exit codes:** the child's own status; **64** = invocation refused; **78** = preflight/configuration failure (chosen so they cannot be confused with ansible's own 1/2/4/…).
- **Vetted shapes.** Playbook mode: `--check/-C --diff/-D --tags/-t --skip-tags --limit/-l --start-at-task -v…-vvvvvv` only, values shape-checked (no `@file` limits, no metacharacters), everything else — extra vars in every spelling, `-m/-a`, `-i`, `--connection`, other playbooks and paths — refused before anything runs. Script mode: only names in the registry, whose entries must resolve inside the repository; arguments are shape-checked and passed as a list (no shell).
- **Ansible's file writes pinned off.** Inherited `ANSIBLE_*` settings that could write or load code (`LOG_PATH`, `CACHE*`, `CALLBACK*`, `LOCAL_TEMP`, `CONFIG`) are **refused**; any other inherited `ANSIBLE_*` is cleared with a note naming it. The effective configuration is then inspected with `ansible-config dump --only-changed` **without the secrets in the environment** and refused if it sets a log file, a non-memory fact cache, a callback outside a print-only allowlist, a non-allowlisted stdout callback or a callback plugin path; a `callback_plugins/` directory anywhere in the tree is refused too (an auto-loading callback could log). Ansible's local temp directory and SSH control sockets are moved to a wrapper-owned 0700 directory (in `$XDG_RUNTIME_DIR` — a tmpfs — when available) that is removed when the run ends. Finding recorded: `ansible-config` itself may touch a configured `log_path`, leaving an *empty* file; the test asserts nothing is ever written to it.
- **The key source and store location are not passed to the child** (`HERMES_SECRETS_KEY_FILE`, `SOPS_AGE_KEY_*`, `HERMES_SECRETS_STORE` are removed from its environment) — asserted.
- **Tier 2 is a configuration change, not a rewrite:** `SOPS_AGE_KEY_CMD` (SOPS's own hook, e.g. a command that unlocks a hardware token) is honoured and skips the key-file checks.
- **`.sops.yaml` is not committed yet, on purpose.** It needs real public keys, which only the operator can generate, and the structural guard (#03) derives "the store is mandatory" from the presence of `.sops.yaml`; committing it before there is a store would fail that guard. The *shape* (recipients scoped by `path_regex` to the store path, one age key per workstation plus a break-glass key in one `key_groups` entry) is proven by the fixture, including that recipients are **not** applied to any other path and that the break-glass key decrypts the same store. The helper (#04) writes the real file at migration (#09).

**Tests (all black-box, fixture only).** Happy path through the real `secrets` resolver role (its values asserted; the target host, `127.0.0.2`, taken from the store and asserted in the recap); no canary value on disk anywhere after a run and the scratch directory removed; exit statuses (playbook 2, script 7, killed-by-signal 137); live streaming; ~21 refused shapes plus script refusals (unregistered, path, registry entry resolving outside the repository *including via a symlink*, non-executable, shell metacharacters), each proven to have run nothing; **every pass-through flag proven to take effect** (a fixture play prints `ansible_check_mode`, `ansible_diff_mode`, `ansible_verbosity` and tagged/ordered markers, so a silently dropped `--check`, `--diff`, `-v`, `--limit`, `--skip-tags`, `--tags` or `--start-at-task` fails); every pinned-off Ansible write refused or neutralized (inherited env settings, `ansible.cfg` log/cache/callback/callback-path/stdout-callback settings, `callback_plugins/`, a logging callback under `~/.ansible`, retry files) with a print-only callback accepted; the configuration inspection **fails closed** (a stub `ansible-config` that fails, or prints garbage, refuses the run) and **never sees the secrets** (the stub records its environment); preflight failures by name only (missing/loose/foreign key, missing/corrupt store, missing names, missing/odd `TARGET_HOST`, reserved names in the store, missing tools); `.env` warning; non-default store path; two-recipient store decrypts with either key; the key source (`HERMES_SECRETS_KEY_FILE`, `SOPS_AGE_KEY`, `SOPS_AGE_KEY_CMD`) and store location are never passed to the child, and `SOPS_AGE_KEY_CMD` (the Tier 2 hook) works.

**Review round 1 (four blocking groups; fixed).** (B1) the pass-through flags were only checked for `rc==0`, never for effect — fixed as above. (B2) `retry_files_enabled = true` in `ansible.cfg` wrote the decrypted target host to `site.retry` — retry files are now pinned off through the environment (which beats the config file; pinning rather than only denylisting, because a denylist over `--only-changed` output is fragile). (B3) a callback plugin under `~/.ansible/plugins/callback/` auto-loaded and could log task results — `ANSIBLE_HOME` now points at an empty directory inside the private scratch directory and `ANSIBLE_CALLBACK_PLUGINS` at an empty one (round 3 corrected an earlier claim here: the two pins are **not** equivalent — `ANSIBLE_HOME` also stops user-level *vars*, *action* etc. plugins from loading, the callback-directory pin only callbacks; each now has its own test). (B4) protective checks that could be removed unnoticed — each now has a test: config inspection failing open, callback-path check, symlink escape, host-from-store (the fixture host now differs from the loopback default), stderr passthrough, signal exit status, `SOPS_AGE_KEY`/`SOPS_AGE_KEY_CMD`/`HERMES_SECRETS_STORE` stripping, non-hinted `ANSIBLE_*` clearing, start-at-task control characters, `TARGET_HOST` shape, secrets kept out of the inspection. Also applied from the non-blocking list: patterns use `fullmatch` (a trailing newline was accepted), a consumer that closes the pipe no longer hangs the child (drain and discard), a grandchild holding the pipes cannot hold the wrapper (bounded join), SIGTERM/SIGHUP/SIGQUIT are forwarded so the scratch directory is removed (SIGINT is not, since a terminal's ^C already reaches the child — forwarding would deliver it twice), a non-executable registered script is refused instead of a traceback, the scratch directory prefers `/dev/shm` if there is no `XDG_RUNTIME_DIR`, the repository's own name-set definition is read *before* any secret is in memory, and **names the store may not hold** (`ANSIBLE*`, `PATH`, `HOME`, `LD_*`, `PYTHON*`, `SOPS_*`, `SSH_*`, …) are refused at preflight, since injected into the child they would change how it runs rather than be a credential. **Mutation-checked:** ~50 mutations across the two rounds, all caught except equivalent ones (the unknown-flag branch — the fall-through still refuses; the paired ANSIBLE_HOME / callback-directory pins, each covering the other's channel).

**Review round 2 (two blocking; fixed).** (B1) a *symlinked* `callback_plugins` bypassed the tree check (`os.walk` lists a symlinked directory but never visits it) and a logging callback then wrote a decrypted value to disk — the check now looks for an entry of that name of any type at every level, with tests for the symlink and for one under `roles/`. (B2) the `ANSIBLE_HOME` pin moved Ansible's *default* collections path, so a workstation with galaxy-installed collections in `~/.ansible/collections` would have lost `ansible.posix`/`community.*` at parse time (the repo's `ansible.cfg` sets the plural `collections_paths`, which Ansible 2.20 ignores) — the wrapper now computes the effective collections path *before* pinning and pins `ANSIBLE_COLLECTIONS_PATH` to it, refusing to run if it cannot be determined; a fixture collection under the fixture `~/.ansible/collections` proves it stays discoverable. Also applied: the reserved-name deny-list became the spec's own name-set rule as an **allowlist** (a store may hold only manifest names and declared extras; each undeclared name is reported by name, tested individually), an empty required value counts as missing, `--tags`/`--limit` values may not start with `-`, `TMPDIR` is pinned into the scratch directory, a scratch parent whose path would exceed ssh's control-socket limit is skipped (`/dev/shm` then `/tmp`), `^C` sent to the wrapper alone no longer produces a traceback (it keeps waiting for the child), `Popen` failures and a malformed manifest are clean errors, and a failing redactor cannot block the child. New tests: stderr/stdout separation, `| head`, a grandchild holding the pipes (bounded wait), SIGTERM forwarding with scratch cleanup, sibling-prefix registry entry, symlinked registry entry. Mutation-checked (all caught except the documented equivalent pair).

**Review round 3 (three blocking; fixed).** (B1) only `callback_plugins` was refused, but Ansible auto-loads *any* plugin/library directory next to the playbook or in a role — a `vars_plugins/` directory ran a plugin that wrote a decrypted value to disk with no config or role edit. The tree check now refuses every such name (`vars`, `action`, `filter`, `lookup`, `connection`, `strategy`, `inventory`, `cache`, `test`, `become`, `terminal`, `httpapi`, `netconf`, `cliconf` plugins, `doc_fragments`, `library`, `module_utils`, `collections`, `ansible_collections`) at any depth, as a directory, a symlink or a file, each with a test. (B2) callbacks were allowlisted by name, but a non-builtin name (`ansible.posix.profile_tasks`) can be shadowed by a `collections/` directory next to the playbook and then runs repository code — the allowlists are now `ansible.builtin` names only (`default`/`minimal`/`oneline` stdout, `timer` notification), `collections/` is refused, and the *validated* callback settings are pinned through the environment so what runs is exactly what was checked. (B3) the `ANSIBLE_HOME` pin had no test of its own (see the correction above) — a vars plugin under `~/.ansible/plugins/vars` is now placed in the fixture and must not run. Also applied: `_ANSIBLE_*` variables are cleared like `ANSIBLE_*`; `ansible-config` is resolved next to `ansible-playbook` so the configuration inspected is that of the Ansible that runs; a closed stdout (`>&-`) no longer crashes the wrapper and orphans the child; the key source used via `SOPS_AGE_KEY_CMD` is announced on stderr (its basename only); the missing-key message names `HERMES_SECRETS_KEY_FILE` (an exported `SOPS_AGE_KEY_FILE` is deliberately ignored); tests now also cover an inherited `SOPS_AGE_KEY_FILE` not reaching the child, the ssh control-socket pin, binary files in the on-disk canary search, and a longer streaming window. Considered and left: `SOPS_AGE_KEY_CMD` from the caller's environment runs a command in the wrapper's context, but `PATH`, `PYTHONPATH` and `LD_PRELOAD` are equally caller-controlled, so it is not a bypass beyond what exists (Tier 1: env-prefixed invocations are not among the exact vetted shapes the permission rules allow, ticket #08); age is public-key encryption, so anyone with write access to the repository can replace the whole store (an authenticity limit, not confidentiality); the stdout-callback pin has no distinguishing test (it only matters between check and use, and is equivalent to the config in every observable case).

**Review round 4 (two blocking; fixed).** (B1) `ansible.cfg` could still load or run code through keys the `--only-changed` dump denylist cannot see or does not name — `vars_plugins`, `vault_password_file` (Ansible executed the script with the decrypted environment) and plugin-level options such as `[ssh_connection] ssh_executable`, which are not in that dump at all. The pinned `ansible.cfg` is now **parsed directly against an allowlist** of sections and keys (exactly what the real file uses, plus a few harmless scalars); any other section or key is refused, and `roles_path`/`collections_path(s)` entries must stay inside the repository (the two well-known collection locations excepted). Each class is tested with its code placed under `.scratch/` (which the tree walk skips), so only the allowlist can be why it is refused; the real repository's own `ansible.cfg` and tree are asserted to pass. The old dump-based checks remain as defence in depth (they also see environment-derived settings). (B2) Python puts `scripts/` first on `sys.path`, so a *new* `scripts/tempfile.py` (or `json.py`, …) shadowed the standard library **inside the wrapper process that holds the decrypted values** — the directory is now moved to the *end* of `sys.path` before any other import and bytecode is never written there; tested by dropping shadow modules for five stdlib names. Also applied: `shell_plugins` added; a test that `ansible-config` is resolved next to `ansible-playbook` (a decoy earlier on `PATH`); `TARGET_HOST` shape tests (leading `-`, embedded newline, space); a whitespace-only `SOPS_AGE_KEY_CMD` no longer crashes the note; signals are installed before the child is started, so a TERM in that window stops cleanly with the scratch directory removed. **Accepted, documented limits.** The target host is passed as `-i host,` and is visible in the process list to local users (it is a hostname, not a credential; `ANSIBLE_INVENTORY` does not accept the `host,` form). Script mode does not pin Ansible's configuration — registered scripts are vetted, and one that itself runs Ansible must do so through this wrapper's playbook mode. A SIGKILL of the wrapper leaves its scratch directory (in a per-user tmpfs). sops' dotenv parser turns a literal backslash-`n` in a value into a real newline; the migration's digest verification (#09) will catch any such alteration.
